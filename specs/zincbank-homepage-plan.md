# Test Plan — ZincBank Homepage Navigation Tabs

> Status: Ready for Test Generator handoff
> Generated by: Planner Agent (live-inspected against https://zincbank.cydeo.io/)
> Requirement: On `https://zincbank.cydeo.io/` the primary navigation must show tabs **PERSONAL**, **BUSINESS**, **CARDS**, **COMPANY**.

---

## Target application (inspected live)

- URL: `https://zincbank.cydeo.io/` · Title: _ZincBank — Banking, quietly exceptional_
- The four required items are rendered as **links** in the **primary navigation** (`role="navigation"`, accessible name "Primary"), title-cased (`Personal`, `Business`, `Cards`, `Company`). The requirement's uppercase forms map to these rendered labels (assert case-insensitively).

### Confirmed real locators (priority-ordered per framework rules)

| Element            | Recommended locator (scoped to primary nav)      | Href target     |
| ------------------ | ------------------------------------------------ | --------------- |
| Primary navigation | `getByRole('navigation', { name: 'Primary' })`   | —               |
| **Personal** tab   | `nav.getByRole('link', { name: /^personal$/i })` | `#features`     |
| **Business** tab   | `nav.getByRole('link', { name: /^business$/i })` | `#features`     |
| **Cards** tab      | `nav.getByRole('link', { name: /^cards$/i })`    | `#feature-card` |
| **Company** tab    | `nav.getByRole('link', { name: /^company$/i })`  | `#footer`       |

> ⚠️ The footer **also** contains a "Cards" link (`#feature-card`), so the four tabs **must** be scoped to the `Primary` navigation to avoid ambiguity.

### Confirmed observable behaviors (from live browser)

- All four tab links are present and visible in the primary nav on the homepage.
- Clicking each tab updates the URL hash to its section target: `Personal`/`Business` → `#features`, `Cards` → `#feature-card`, `Company` → `#footer` (same-page anchors — the page does not navigate away).

---

## ⚠️ Integration caveats (hand these to the Test Generator)

1. **Scope tab locators to the `Primary` navigation** — the footer also exposes a "Cards" link; unscoped `getByRole('link', { name: 'Cards' })` would match two elements and fail on strictness.
2. **Frame as navigation links, not literal ARIA tabs.** The requirement calls them "tabs", but the DOM exposes them as `role="link"` inside `role="navigation"`. Do not use `getByRole('tab')` — it will not match.
3. **Test-id attribute mismatch.** The framework registers `data-test`; ZincBank uses `data-testid`, so prefer `getByRole`/`getByText` and do not depend on `getByTestId`.
4. These are same-page anchor links (`#...`) — assert the hash in the URL, not a route change.

## Feature: ZincBank Homepage Navigation

**Preconditions:** none (public homepage; no auth required). `config.baseUrl` = ZincBank.

### Scenario 1 — Homepage shows the four primary navigation tabs

- Priority: **Critical** · Tag: `@smoke @critical`
- **Given** I open the ZincBank homepage
- **Then** the primary navigation shows the tabs "Personal", "Business", "Cards", and "Company"

### Scenario 2 — Each tab navigates to its target section

- Priority: **High** · Tag: `@smoke`
- **Given** I open the ZincBank homepage
- **When** I click the "Personal" tab
- **Then** the page scrolls to the "#features" section

(Data-driven via an Examples table: `Personal → #features`, `Business → #features`, `Cards → #feature-card`, `Company → #footer`.)
